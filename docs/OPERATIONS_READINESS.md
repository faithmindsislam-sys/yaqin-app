## Implemented cost, deadline and auth controls

Server-only `agent_private.model_budgets` holds four atomic counters per service: user/service minute admissions and user/service UTC-day conservative token reservations. Shared row updates and a single transaction prevent replica races; denial rolls back all counters, including a first reservation exceeding a cap. Keys come from verified account IDs, never forwarded IP or JWT metadata. Missing ledger/permission/database availability fails closed before spending. The memory ledger is local-only; production already requires Postgres.

Defaults: 12 admissions/user/minute, 500/service/minute, 10 million reserved units/user/day, 100 million/service/day. YAQIN reserves the full operation cap; standalone lesson admission reserves three complete generation runs, including billable failures/recovery. These are conservative **admission reservations**, not measured dollar expenditure; unused reservations are intentionally not refunded. Fixed windows can admit adjacent-window bursts. Pending jobs can execute on a later day: daily admission limits are not a provider invoice-day limit. Drain old queued jobs before changing worker caps, keep API/worker caps consistent, and configure Lambda concurrency/queue alarms before rollout.

| --- | ---: | ---: | ---: |

| YAQIN check/publication | 180 (up to 300) | 800,000 | 12 |

Reservation estimates count UTF-8 input, output limits, schemas/overhead and repeated moderation input. They deliberately exceed expected provider tokens. Each moderation input also has a complete 100,000-character ceiling and operation assessment count ceiling. No prefix-only assessment is accepted. Model calls reserve before invocation, retain charges on exceptions, and have bounded outputs. YAQIN SDK retries are disabled: at most two schema attempts, contained by the whole-operation call cap; moderation/support rejection is never a retry signal. Standalone clients use one SDK attempt and close reliably. YAQIN uses an async deadline; standalone uses Unix main-thread wall timers (Lambda's execution contract), and fails closed on unsupported threaded/non-Unix invocation. Nested retrieval, moderation, support and final rechecks share the operation deadline. Cancellation/socket interruption cannot cancel or unbill already-started provider work.

Remote Ask requires both services' independently authenticated reservations. YAQIN's reservation covers its router/embedding/moderation/support work; standalone covers its answer/support and library checks. Do not report these as one actual provider charge. Auth/JWKS have independent bounded network waits and profile reads. Standalone rejects anonymous JWTs. YAQIN rejects missing/banned profiles and emits fixed verification errors. Persisted profiles decide staff authority; client JWT metadata never grants it.

Metadata logs contain fixed events/reasons, status, track, latency, model calls, reservations and measured model-token totals only. Actual totals are null unless every started model call reports usage; embeddings without recorded usage keep the aggregate unknown. Guardrail units are not model tokens. No transcript, original source text, JWT, provider exception, or DB URL is logged. Owned staff job rows intentionally retain original audit evidence; they are not telemetry. `tokensUsed` remains null; new `reservedTokens`, `actualTokens`, and `modelCalls` are distinct. Release collection accepts the new true totals without inventing input/output splits; all unavailable metrics stay null. No Langfuse project/cloud write was performed.

Provider counts are now recorded per call in `agent_private.model_usage`, separately from reservations. A unique call ID is committed before invocation; returned input/output/cache token counts complete that same row before parsing, moderation, or client cleanup can fail. Retries create new rows; duplicate completion cannot add spend twice. NULL tokens identify interrupted calls or absent/invalid provider usage. UTC day is the call's start day, including workers executing after their admission day. YAQIN includes Titan embedding input counts; remote Ask is counted only in standalone. Guardrail assessment units and external RAG infrastructure are not included in these model-token totals.

Studio's user list and details show the sum of received, recorded provider counts per service plus unknown-call counts. The recorded subtotal starts at zero, including when started calls have no returned counts; unknown calls remain flagged. Unreadable tables or hidden cross-service data remain unavailable. These totals cover new recorded calls only; reservations cannot reconstruct earlier consumption. Cache totals use the providers' documented separate input categories ([Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html), [Messages](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)). Tokens are consumption counts, not currency or invoices. The 10,000,000 daily allowance and existing reservation enforcement remain independent.

## YAQIN draft lifecycle contract

No automatic queue was added. Jobs have an explicit safely interrupted terminal contract. The API starts one bounded in-process task; a recurring 30-second sweep and authenticated polling terminalize running jobs after their configured course deadline plus 30 seconds from creation. Graceful shutdown cancels/awaits local tasks before closing storage. Abrupt process loss leaves a running row until any healthy replica/poll observes expiry; restart starts the sweeper. If no replica is running, visibility is delayed until restart/poll. Alert on overdue rows/recovery failures.

A generated course uses a job-derived stable ID. Completion locks the owned running job, validates its expiry, and saves course, curriculum placement, review event and terminal job result in one transaction. Failure rolls back the entire write. Terminal jobs cannot be resurrected by progress/completion updates. Late/duplicate runners cannot create orphan or duplicate courses. A teacher's explicit retry creates a new job and reservation. Status remains `failed` with fixed `reason_code=generation_interrupted`; existing Studio and evaluator terminal-state handling already recognizes it. Safe localized text distinguishes no sources, moderation/support rejection, changed sources, interruption and generic failure. Raw exception strings are neither persisted nor returned. The saved audience is retained.

Standalone jobs retain their existing Postgres outbox, retry leases, claim fencing and session advisory locks. Worker Lambda timeout **300s**, dispatcher timeout **60s**, generation budget **240s**, scheduler **every minute** must be configured/activated in the real environment. Worker connections require direct/session pooling, not transaction pooling. The existing 360s idle-session and 30s idle-in-transaction timeouts bound abandoned locks. Local CI proves neither scheduler activation nor live crash recovery.

## Final lesson evidence and display contract

Immediately before persisting either a completed candidate or an editorial-only review candidate, standalone re-retrieves every cited card/quiz passage within its original resource scope and authoritative worker identity. It compares complete original text, document/resource identity, source/URI/language; unknown/missing/changed/ineligible/unavailable evidence withholds the whole candidate without redrafting around rejection. Ranked retrieval can conservatively withhold an eligible cited passage that no longer appears in top-k. Unused retrieved passages are not grounds for withholding.

Only code-valid, independently grounded/on-topic candidates can be retained for editorial review. Unsupported/invalid/unjudged candidates and claim-bearing authoring notes are absent from withheld terminal results. Original staff audit evidence may remain; release evaluation distinguishes that original evidence from generated claims without relaxing learner checks. A final recheck is a point-in-time decision, not a transaction with the remote RAG store. A long-lived `NEEDS_REVIEW` result is a historical staff snapshot, not permission to publish or certify current eligibility; revalidate all original evidence at any subsequent import/publication boundary. There is no new publication route in standalone.

Its `build` path rolls an existing task definition; the full path is required to change task environment/IAM. Do not use a mutable image tag as rollback evidence: record the deployed digest and previous task definition.
