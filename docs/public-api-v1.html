01 · Authentication

An account, then an access token.

You need a Yaqeen account, not a Supabase dashboard account. A personal script can create an account and sign in through Supabase Auth without using Yaqeen's login form. There is no separate Yaqeen /login endpoint.

Supabase Auth project
https://okcctzpfpreziuxnyepk.supabase.co
Publishable key
YOUR_SUPABASE_PUBLISHABLE_KEY

These connection values are public. They identify the project; they do not grant account access. Keep passwords, access tokens and refresh tokens private.

1. Create your account once

If you already have a Yaqeen account, skip to sign-in. Check your inbox and click the confirmation link before signing in. Email confirmation is required. You do not need to use the website’s signup form.

curl "https://okcctzpfpreziuxnyepk.supabase.co/auth/v1/signup" \
  -H "apikey: YOUR_SUPABASE_PUBLISHABLE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","password":"YOUR_ACCOUNT_PASSWORD"}'

2. Sign in to get your tokens

The response contains access_token, refresh_token and expires_in. Use only access_token for API requests. The publishable key identifies the Auth project; it is not your API access token.

curl "https://okcctzpfpreziuxnyepk.supabase.co/auth/v1/token?grant_type=password" \
  -H "apikey: YOUR_SUPABASE_PUBLISHABLE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","password":"YOUR_ACCOUNT_PASSWORD"}'

3. Refresh when the access token expires

Store both replacement tokens securely. If refresh fails, sign in again. The Supabase SDK can refresh automatically.

curl "https://okcctzpfpreziuxnyepk.supabase.co/auth/v1/token?grant_type=refresh_token" \
  -H "apikey: YOUR_SUPABASE_PUBLISHABLE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"refresh_token":"YOUR_CURRENT_REFRESH_TOKEN"}'

Password login is for your own account or script. Partner apps should use a user-authorized sign-in flow instead of collecting users' passwords. Google sign-in also works through the interactive Supabase flow; use its Supabase access token, not a Google token. A Google-only account needs a configured password for password login.

API keys and machine credentials are not available in this release. Never use a Supabase secret/service-role key, refresh token or publishable key as the Yaqeen bearer token. Supabase Auth errors use Supabase's error format.

02 · Quick start

Make your first request.

Set YAQIN_ACCESS_TOKEN privately to the token returned by sign-in, then list published courses. Every API operation requires an active signed-in account.

curl "https://public-api.yaqeenguide.com/api/v1/courses?limit=25" \
  -H "Authorization: Bearer $YAQIN_ACCESS_TOKEN"

To test in Swagger, select Authorize, paste only your access_token (without the Bearer prefix), then choose an operation → Try it out → Execute.

Expect HTTP 200 and JSON containing items, total, offset and limit. Use a returned course ID to fetch its detail. External browser integrations need their exact origin approved for CORS.

Preserve the evidence. Keep source attribution, grading, review/translation status and referrals visible. Do not invent missing translations. Drafts, archives and Coming soon courses are unavailable. Course detail may return 409 if its sources await approval; source reads return 404 without an approved canonical record.

Render tutor answer blocks in order, resolving source IDs through the response's sources map. Check tier, ai_generated and safety_outcome: HTTP 200 can contain a refusal or referral. Label AI answers and temporary practice exercises. HTTP tutoring may cite eligible unreviewed library passages that cannot be fetched through the canonical source endpoint; MCP tutoring uses approved sources only.

04 · MCP

The same capabilities, as tools.

Use a remote client that supports Streamable HTTP. All four tools are anonymous and rate-limited. No account, OAuth registration, callback, client secret or bearer token is needed.

MCP server URLhttps://public-api.yaqeenguide.com/api/v1/mcp/
  1. Add the server URL to your MCP client.Keep the final slash; hosted Claude's slashless form is also accepted.
  2. Select authentication: None.Recreate old OAuth connections without authentication.
  3. Select a tool.The client discovers all four tools. Start by listing published courses.
ToolArgumentsReturns
list_coursesoffset, limit, optional trackThe published course page
get_coursecourse_idCourse content and approved citations
get_sourcesource_idAn approved canonical source
ask_tutorrequest: the HTTP tutor input objectA cited tutor answer; spends model quota

Example MCP tools/call parameters · a course read

{"name":"list_courses","arguments":{"offset":0,"limit":3}}

Tool schemas come from tools/list. Results use structuredContent and content blocks. Check result.isError, even with HTTP 200. Quota/content failures include JSON text with error and numeric status; transport throttling returns HTTP 429 with Retry-After. Invalid arguments may return plain MCP error text.

No sign-in is required for MCP.Authorization headers are ignored. The tools expose published courses and approved sources; tutoring uses those sources in-process and has no account or private learner progress.

Guest limits use the viewer IP (IPv6 /64), with shared service caps. Users behind the same NAT or hosted connector share limits. Every MCP HTTP request counts, including initialization and tool listing. Check HTTP 429 and Retry-After, and result.isError for model quota failures. Quota-storage outages fail closed.

05 · Operations

Limits, errors and retries.

These are configurable defaults, not a pricing plan. Limits are shared across an account's tokens, clients and IP addresses, using fixed UTC minute/day windows.

AllowancePer accountAcross service
API requests / MCP HTTP requests per minute60500
Model operations / minute, shared with the app12500
Model token reservations / UTC day10,000,000100,000,000

Each tutor request reserves 200,000 model tokens as a conservative ceiling, not measured usage. Reads reserve no model tokens; failed operations are not refunded. Every MCP HTTP request counts. MCP per-account column values apply per guest IP (IPv6 /64); shared model limits also cover app/API activity. Default tutoring caps allow up to 50 guest calls/day and 500 shared calls/day. Maximum request body: 64 KiB.

HTTP statusWhat to do
400Correct invalid input. Unknown top-level tutor fields are rejected.
401Supply a valid token; refresh or sign in again.
403Account unavailable or access denied. Resolve access before retrying.
404Course/source unavailable.
409Course citations awaiting approval.
413Reduce the body below 64 KiB.
429Wait for the allowance or model budget to reset.
500 / 503Use bounded backoff for temporary server, auth, quota or model failures.
{"error":{"code":"rate_limited","message":"Public API request limit exceeded."}}

Check error.code instead of matching message text. For rate_limited, wait the HTTP Retry-After seconds. A quota_exceeded daily budget can remain exhausted until the next UTC day. Tutor calls have no idempotency key: retries can spend quota again. Responses use Cache-Control: no-store.

MCP transport can additionally return 421 for an untrusted host. HTTP API authentication errors use 401/403; MCP needs no authentication. Outages use 503. Keep credentials out of URLs, logs, source code and prompts.
